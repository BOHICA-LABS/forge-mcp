# ADV-P1-002 — CLI elicitation rejection conflicts with MCP host behavior requirements

**Severity:** HIGH  
**Category:** contradiction  
**Affected artifacts:** BC-2.05.005, domain-research.md §1.2/§1.4

## Description
BC-2.05.005 says CLI mode rejects every `elicitation/create` request with `action: "decline"` because there is no interactive user. That hardcoded behavior conflicts with the product positioning as a CLI/TUI inspector and with the protocol model in domain research where the client/host is responsible for handling server-initiated requests. A non-interactive CLI still needs a specified machine-usable contract: pre-supplied answers, stdin mode, callback URL, or a protocol-level error/decline policy aligned with actual MCP elicitation result semantics. Right now the spec assumes `decline` is always valid without grounding that in the protocol details.

## Proposed Resolution
Amend BC-2.05.005 and interface definitions to specify one of: (a) explicit non-interactive decline only when `--non-interactive` is set, with a protocol-correct elicitation result shape backed by domain research; or (b) a CLI answer source such as stdin/JSON file. Add protocol references for the exact allowed elicitation response actions.
