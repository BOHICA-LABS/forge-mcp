# ADV-P1-016 — No VP covers daemon multiplexing correctness despite pooled-session risk

**Severity:** HIGH  
**Category:** verification-gap  
**Affected artifacts:** BC-1.03.001, VP-INDEX, module-criticality.md

## Description
BC-1.03.001 relies on correct request/response routing across shared pooled sessions. Module criticality still marks forge-daemon only MEDIUM with zero VPs. That underestimates the blast radius: misrouting can leak data between clients, corrupt replies, or attach server-initiated events to the wrong user. Integration tests alone are weak for a multiplexing state machine.

## Proposed Resolution
Promote the daemon session router or its pure routing core to a formal verification target. Add a VP for request/response demultiplexing correctness and reconsider forge-daemon criticality if shared-session routing remains in scope.
