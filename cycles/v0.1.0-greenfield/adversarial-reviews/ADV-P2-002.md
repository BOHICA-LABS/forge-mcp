# ADV-P2-002 — HTTP transport contract still references error codes that now mean different failures

- **Severity:** HIGH
- **Category:** contradiction
- **Location:** `.factory/specs/behavioral-contracts/BC-1.02.002.md`, `.factory/specs/prd-supplements/error-taxonomy.md`

## Description

The Streamable HTTP connection contract still cites error codes whose meanings conflict with the central taxonomy. That leaves implementers unable to know whether to follow the BC or the taxonomy when reporting TLS, authentication, timeout, and DNS failures.

## Evidence

`BC-1.02.002` says:
- TLS failure → `E-CON-005`
- HTTP 401/403 → `E-CON-007`
- insecure HTTP warning → `E-CON-008`
- DNS failure → `E-CON-009`
- HTTP 502/503/504 → `E-CON-010`
- timeout → `E-CON-004`

But `error-taxonomy.md` defines:
- `E-CON-004` = TLS error
- `E-CON-005` = capability negotiation rejected
- `E-CON-007` = Streamable HTTP session lost
- `E-CON-008` = session re-established
- there is **no** `E-CON-009` or `E-CON-010` entry at all

So the same code names two different failures, and some BC-referenced codes do not exist centrally.

## Proposed Fix

Normalize `BC-1.02.002` to the taxonomy (or update the taxonomy, but pick one source of truth). Every connection edge case in the BC must reference an existing `E-CON-*` code with identical semantics, and any new code introduced for HTTP-specific failures must be added to `error-taxonomy.md` in the same pass.
