# ADV-P1-015 — Cancellation message shape is underspecified against MCP progress/cancel model

**Severity:** HIGH  
**Category:** protocol-error  
**Affected artifacts:** BC-2.05.009, domain-research.md §1.7

## Description
BC-2.05.009 says Forge sends `notifications/cancelled` with `{requestId, reason}` and tracks progress by `_meta.progressToken`. Domain research only states that either side can send `notifications/cancelled` with the request ID, but the contract never anchors the exact field names or relation between request ID and progress token to the MCP 2025-11-25 schema. That is dangerous because cancellation semantics are protocol-shape-sensitive, and the rest of the spec assumes rmcp-managed correctness without writing down the exact contract.

## Proposed Resolution
Update domain research and BC-2.05.009 with the exact 2025-11-25 cancellation notification schema and explicitly define whether Forge keys internal state by request ID, progress token, or both. Add canonical examples using the spec-accurate payload shape.
