# BC-7.16.004 — Finding Severity Classification with Confidence Scores

## Summary

Every security finding carries both a severity level (critical/high/medium/low/info)
and a confidence score in [0.0, 1.0]. Confidence 1.0 means deterministic detection
(exact pattern match, known-bad value). Confidence < 1.0 means heuristic detection
(behavioral anomaly, contextual pattern). Classification rules are documented and
user-visible.

## Preconditions

| ID | Condition |
|----|-----------|
| PRE-001 | A security finding has been generated by one of the detection contracts (BC-7.16.001 through BC-7.17.003) |
| PRE-002 | The finding includes raw evidence (matched text, schema field, IP address, etc.) |

## Postconditions

| ID | Condition |
|----|-----------|
| POST-001 | Every finding has a `severity` field: one of `critical`, `high`, `medium`, `low`, `info` |
| POST-002 | Every finding has a `confidence` field: a float in [0.0, 1.0] |
| POST-003 | Confidence 1.0 is assigned only for deterministic matches (exact IP, exact pattern keyword in tool name) |
| POST-004 | Confidence < 1.0 is assigned for heuristic matches (keyword in description context, behavioral pattern) |
| POST-005 | The classification rules (severity × confidence matrix) are documented in a user-accessible location |
| POST-006 | Findings can be filtered by severity and/or confidence in the audit report |
| POST-007 | The combination of severity + confidence enables risk-based prioritization |

## Classification Rules

### Severity Assignment

| Detection Type | Condition | Severity |
|---------------|-----------|----------|
| Code execution pattern in tool name | `exec`, `eval`, `shell` in name | Critical |
| Code execution pattern in description only | `exec`, `eval`, `shell` in desc | High |
| Cloud metadata endpoint | `169.254.169.254` | Critical |
| Loopback address | `127.0.0.0/8` | High |
| Private IP (RFC 1918) | `10/8`, `172.16/12`, `192.168/16` | Medium |
| Schema drift (description changed) | Hash mismatch | High |
| Schema drift (new tool added) | Tool not in baseline | Info |
| Permission escalation | Undeclared capability | Critical |
| Root boundary violation | Path outside roots | High |
| Auth token in response | Token pattern match | High |

### Confidence Assignment

| Evidence Quality | Confidence | Example |
|-----------------|------------|---------|
| Exact known-bad value | 1.0 | `169.254.169.254` in response |
| Exact keyword in tool name | 1.0 | Tool named `exec_command` |
| Keyword in description (clear context) | 0.9 | Description: "executes shell commands" |
| Keyword in description (ambiguous context) | 0.6–0.8 | Description: "executes the search query" |
| Schema field name match | 0.8 | Input field named `command` |
| Behavioral anomaly | 0.5–0.7 | Tool returned more data than expected |
| Indirect indicator | 0.3–0.5 | Tool has unusually broad input schema |

## Invariants

| ID | Invariant |
|----|-----------|
| DI-011 | Confidence scores are in [0.0, 1.0]; 1.0 = deterministic, < 1.0 = heuristic |

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Tool named "execute_query" — is this code exec or DB query? | Severity: high (exec keyword), confidence: 0.7 (ambiguous context) |
| EC-002 | Multiple evidence sources for same finding (name + description + schema all match) | Confidence boosted: min(1.0, base_confidence + 0.1 per additional source) |
| EC-003 | Finding with confidence 0.3 | Included in report but severity alone determines blocking; low confidence noted |
| EC-004 | All findings have confidence 1.0 | Valid: all detections were deterministic |
| EC-005 | User wants to ignore findings below confidence 0.5 | Supported via `--min-confidence 0.5` filter |
| EC-006 | Same tool triggers two rules with different severities | Two separate findings, each with own severity + confidence |

## Canonical Test Vectors

### Happy Path

| Finding Source | Evidence | Severity | Confidence |
|---------------|----------|----------|------------|
| Tool named `run_shell` | Name contains "shell" | Critical | 1.0 |
| `169.254.169.254` in response | Exact metadata IP | Critical | 0.95 |
| Tool desc "reads files from disk" | "reads files" pattern | Medium | 0.9 |
| Schema field `url` of type string | Network indicator | Low | 0.5 |
| Schema hash changed | SHA-256 mismatch | High | 1.0 |

### Edge Case

| Finding Source | Evidence | Severity | Confidence |
|---------------|----------|----------|------------|
| Tool "execute_search" | "execute" in name | High | 0.7 |
| Tool "execute_search" with desc "runs a search query" | Name + desc ambiguous | High | 0.8 (boosted) |
| `10.0.0.1` in response | Private IP | Medium | 0.70 |

### Error

| Scenario | Expected Behavior |
|----------|-------------------|
| Finding generated without evidence | Rejected: DI-010 violation. Finding not recorded. |
| Confidence calculated as > 1.0 (bug) | Clamped to 1.0; warning logged |
| Confidence calculated as < 0.0 (bug) | Clamped to 0.0; warning logged |

## Verification Properties

| ID | Property | Type |
|----|----------|------|
| VP-001 | Confidence is always in [0.0, 1.0] | Property test |
| VP-002 | Deterministic detections (exact match) always have confidence 1.0 | Unit test |
| VP-003 | Severity is always one of the 5 defined levels | Unit test |
| VP-004 | Classification rules are deterministic: same evidence → same severity + confidence | Property test |
| VP-005 | Multiple evidence sources boost confidence (never decrease it) | Unit test |
| VP-006 | Findings without evidence are rejected | Negative test |
