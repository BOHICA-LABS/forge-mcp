# ADV-P1-005 — Dependency graph violates its own downward-flow rule

**Severity:** HIGH  
**Category:** architecture-concern  
**Affected artifacts:** dependency-graph.md, module-decomposition.md

## Description
The dependency graph says dependencies flow downward and “core depends on nothing internal.” Then it declares `forge-discovery -> forge-core` and `forge-config -> forge-discovery + forge-core`. The ASCII DAG, however, places `forge-config` below `forge-discovery` and both above `forge-core`, implying the opposite flow. Worse, `forge-discovery` is described as config parsing but depends on `forge-core` solely for shared MCP types, which couples a discovery/config concern to the protocol adapter. The architecture is internally inconsistent about what “lower-level” means.

## Proposed Resolution
Normalize the layering model. Either move shared non-protocol types into a dedicated foundation crate, or explicitly redefine forge-core as a shared domain/kernel crate rather than only a protocol adapter. Then redraw the DAG to match the dependency table and direction rule.
