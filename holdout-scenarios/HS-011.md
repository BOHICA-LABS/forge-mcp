# HS-011 — Elicitation request in non-interactive CLI mode

## Description

A developer is using Forge MCP's CLI (non-interactive) to invoke a tool on an MCP
server. During the tool invocation, the server sends an `elicitation/create` request
expecting an interactive form to be presented to the user (e.g., asking for
confirmation or additional parameters). However, the CLI mode cannot display
interactive forms — there is no TUI, no terminal UI, just piped JSON output.

Forge MCP must handle this gracefully: return an appropriate error to the server,
log details to stderr for debugging, and not crash or hang waiting for user input
that will never come.

## Setup

1. Create a mock MCP server with a tool `deploy` that:
   - When called, sends an `elicitation/create` request before completing:
     ```json
     {
       "method": "elicitation/create",
       "params": {
         "message": "Are you sure you want to deploy to production?",
         "requestedSchema": {
           "type": "object",
           "properties": {
             "confirm": {
               "type": "boolean",
               "description": "Confirm production deployment"
             },
             "reason": {
               "type": "string",
               "description": "Deployment reason"
             }
           },
           "required": ["confirm"]
         }
       }
     }
     ```
   - On receiving an error response for elicitation, returns a tool result:
     ```json
     {
       "content": [{"type": "text", "text": "Deployment cancelled: user confirmation unavailable"}]
     }
     ```
2. Start the server

## Steps

1. Run in non-interactive CLI mode:
   ```bash
   forge-mcp call elicit-server deploy '{"target": "production"}' --json
   ```
2. Observe behavior when elicitation request arrives
3. Check stderr for diagnostic output
4. Check stdout for the final tool result
5. Verify the process exit code
6. Pipe the command output to verify it doesn't break pipelines:
   ```bash
   forge-mcp call elicit-server deploy '{"target": "production"}' --json 2>/dev/null | jq .
   ```

## Expected Behavior

- Forge MCP receives the `elicitation/create` request from the server
- Detects that it is running in non-interactive CLI mode (no TUI session)
- Returns a JSON-RPC error to the server indicating:
  - Elicitation is not supported in non-interactive mode
  - The user cannot provide the requested input
- Logs to stderr:
  - Warning that an elicitation request was received but cannot be fulfilled
  - The elicitation message ("Are you sure you want to deploy to production?")
  - Suggestion to use TUI mode for interactive workflows
- The server receives the error and handles it (returns tool result with cancellation)
- stdout contains only the final JSON tool result
- The process does not hang, block, or prompt on stdin
- Exit code: 0 (the tool call completed, even if the server cancelled its action)
- Pipeline-safe: stderr goes to stderr, stdout has only valid JSON

## Must-Pass Criteria

1. Process does not hang or block waiting for input
2. Error is returned to the server (not silently dropped)
3. stderr contains diagnostic information about the elicitation
4. stdout contains only valid JSON (no mixed human/machine output)
5. Process exits within a reasonable time (< 5 seconds)

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Non-blocking behavior | Hangs waiting for input | Times out after long delay (> 30s) | Returns quickly but unclear error | Returns immediately with proper error |
| Error to server | No error sent, dropped | Generic error, no context | Proper error code + message | Error code + reason + capability note |
| stderr diagnostics | Nothing on stderr | Error message only | Warning + elicitation details | Warning + message + schema + TUI suggestion |
| stdout cleanliness | Non-JSON on stdout | JSON with extra text | Valid JSON, minor extra fields | Clean minimal JSON, pipeline-safe |
| Pipeline safety | Breaks downstream pipes | Works with 2>/dev/null hack | Works without redirection, minor noise | Clean separation: JSON on stdout, diagnostics on stderr |
