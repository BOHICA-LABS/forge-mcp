# HS-013 — Mixed protocol version environment

## Description

A developer has two MCP servers in their environment running different protocol
versions. One uses the latest MCP spec (2025-11-25) with streamable HTTP transport
and extended capabilities. The other uses the older spec (2024-11-05) with basic
stdio transport. The user connects to both and expects Forge MCP to handle the
version differences gracefully — inspecting capabilities, noting version differences,
and running conformance tests that are version-appropriate.

This tests Forge MCP's ability to operate in heterogeneous protocol environments,
which is the reality for most users during the MCP ecosystem's rapid evolution.

## Setup

1. **Server A (modern)** — MCP 2025-11-25:
   - Transport: Streamable HTTP on port 8080
   - Capabilities: tools, resources, prompts, sampling, elicitation
   - Protocol version in `initialize` response: `"2025-11-25"`
   - Implements pagination for `tools/list`
   - Has 5 tools with rich inputSchema

2. **Server B (legacy)** — MCP 2024-11-05:
   - Transport: stdio
   - Capabilities: tools only
   - Protocol version in `initialize` response: `"2024-11-05"`
   - No pagination support
   - Has 3 tools with basic inputSchema

## Steps

1. Run `forge-mcp connect server-a`
2. Run `forge-mcp connect server-b`
3. Run `forge-mcp info server-a --json` — note protocol version and capabilities
4. Run `forge-mcp info server-b --json` — note protocol version and capabilities
5. Run `forge-mcp test server-a --json` — conformance test for modern server
6. Run `forge-mcp test server-b --json` — conformance test for legacy server
7. Compare the capability sets reported for each server

## Expected Behavior

- Both servers connect successfully despite different protocol versions
- `info` output for each server includes:
  - Protocol version (2025-11-25 vs 2024-11-05)
  - Transport type (HTTP vs stdio)
  - Declared capabilities list
  - Tool count and schema details
- Conformance tests are version-appropriate:
  - **Server A:** Tests sampling, elicitation, pagination, resources, prompts
  - **Server B:** Tests only tools (does NOT test features not in 2024-11-05 spec)
- No false failures from testing features against a server that predates them
- Forge MCP negotiates the protocol version during `initialize` correctly for each
- Info output clearly indicates which protocol features are available per server
- Version differences are surfaced in a useful way (e.g., "server-b: elicitation not
  available (protocol version 2024-11-05 predates this feature)")

## Must-Pass Criteria

1. Both servers connect successfully (version negotiation works)
2. Protocol version is correctly reported for each server
3. Conformance tests do not test features absent from a server's protocol version
4. No false failures from version mismatch
5. Capability reporting accurately reflects each server's declared capabilities

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Version negotiation | Can't connect to one version | Both connect, version not tracked | Both connect, version reported | Both connect, version drives behavior |
| Capability reporting | Same capabilities shown for both | Different but inaccurate | Accurate per server, no version context | Accurate + version-annotated capabilities |
| Conformance scoping | Same tests for both versions | Mostly same, some skipped | Tests scoped by version, minor leaks | Perfectly scoped: only tests applicable features |
| Transport handling | Only one transport works | Both work, minor issues | Both work cleanly | Both work + transport type visible in info |
| User communication | No version info shown | Version shown, no implications | Version + missing features noted | Version + feature matrix + upgrade suggestions |
