# ADV-P1-010 — Session pooling spec lacks isolation rules for server-initiated requests across shared clients

**Severity:** HIGH  
**Category:** spec-gap  
**Affected artifacts:** BC-1.03.001, HS-INDEX

## Description
BC-1.03.001 says CLI and TUI clients can share the same pooled MCP session and requests are multiplexed by client session ID. Cute. But the spec never defines how server-initiated requests/notifications are routed when one pooled server session is shared by multiple clients. Sampling, elicitation, progress, logging, and roots requests are session-scoped protocol messages, not obviously attributable to a single originating client. Without a routing rule, pooled sharing can misdeliver interactive prompts or leak data across clients.

## Proposed Resolution
Add a contract for pooled-session event routing. Define whether pooled sessions are allowed only for passive observation, whether interactive server-initiated requests pin the server connection to one owning client, or whether the daemon fans out some classes of messages and rejects others. Add a holdout for concurrent shared-session elicitation.
