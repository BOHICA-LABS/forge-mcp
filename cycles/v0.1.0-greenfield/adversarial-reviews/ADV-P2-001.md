# ADV-P2-001 — Daemon multiplexing isolation is still unverified despite shared-session requirement

- **Severity:** HIGH
- **Category:** verification-gap
- **Location:** `.factory/specs/behavioral-contracts/BC-1.03.001.md`, `.factory/specs/verification-properties/VP-INDEX.md`, `.factory/specs/architecture/verification-coverage-matrix.md`

## Description

Pass 1’s shared-session routing risk is still not actually closed. The spec continues to require pooled MCP connections shared across concurrent TUI/CLI clients, but the verification set still has no property that proves response routing isolation or server-initiated callback isolation for multiplexed clients. HS-018 explicitly stress-tests this exact failure mode, so the traceability chain still breaks at L4.

## Evidence

- `BC-1.03.001` requires pooled reuse of a single server connection across clients and says “Responses are routed to the correct client session” (`POST-003`, `POST-004`, `EC-002`, `VP-003`).
- `HS-018` requires “No cross-talk between concurrent CLI calls” and “Data integrity — CLI call A's response is never delivered to CLI call B.”
- `VP-INDEX.md` still catalogs only **14 verification properties** and contains no daemon/session-pool VP.
- `verification-coverage-matrix.md` still lists `forge-daemon` under “Modules without VPs (by design)” even though this module now carries shared-session correctness risk.

## Proposed Fix

Add a dedicated VP for daemon multiplexing correctness, at minimum covering:
1. request/response routing isolation across concurrent client session IDs,
2. handling of server-initiated callbacks (sampling, elicitation, progress, list_changed) when multiple clients share a pooled server session,
3. no response duplication or loss under interleaved requests,
4. trace the new VP in `VP-INDEX.md` and `verification-coverage-matrix.md` so HS-018 is no longer orphaned at L4.
