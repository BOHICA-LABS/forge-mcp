# ADV-P2-004 — Traffic replay UX still omits the mandatory explicit target-selection step

- **Severity:** MEDIUM
- **Category:** ux-inconsistency
- **Location:** `.factory/specs/behavioral-contracts/BC-4.10.003.md`, `.factory/specs/ux-spec/flows/FLOW-003-traffic-inspection.md`, `.factory/specs/ux-spec/screens/SCR-004-traffic-inspector.md`

## Description

Replay remains unsafe in the UX spec. The BC requires explicit target designation and confirmation before any replay, but the flow and screen still model `R` as a direct action with no target-selection or confirmation dialog. That means the user journey still violates DI-007 at the interaction layer.

## Evidence

- `BC-4.10.003` preconditions require: `PRE-002` explicit target designation and `PRE-004` user confirmation.
- `BC-4.10.003` also states replay “never sends to the original server unless the user explicitly designates it as the target.”
- `FLOW-003` step 11 says simply: “`R` to replay request → New request sent to server.” No target picker, no confirmation.
- `SCR-004` keyboard shortcuts and detail views expose `[ R: Replay ]`, but the screen has no replay-target control, no warning dialog, and no comparison target state.

## Proposed Fix

Add an explicit replay workflow to the UX spec:
1. replay target selector (server picker or command prompt),
2. confirmation dialog before sending,
3. warning when target equals original server,
4. progress/report surface matching BC-4.10.003 comparison semantics.

Until that exists, the UX still encourages a non-compliant one-keystroke replay.
