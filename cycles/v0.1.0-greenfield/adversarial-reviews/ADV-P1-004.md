# ADV-P1-004 — “Proxy layer” is underspecified and architecture never assigns it cleanly

**Severity:** MEDIUM  
**Category:** ambiguity  
**Affected artifacts:** BC-4.09.001, system-overview.md, module-decomposition.md

## Description
BC-4.09.001 requires capture of all JSON-RPC traffic “through Forge’s proxy layer,” but the architecture only describes a thin rmcp wrapper plus application crates. There is no explicit proxy boundary, interception hook, or ownership definition for stdio vs HTTP vs daemon-mediated traffic. That matters because transparent capture, byte-identical replay, and server-initiated message handling all depend on exactly where interception happens.

## Proposed Resolution
Add an explicit architectural component and ownership rule for the capture interception point per transport. Specify whether interception occurs inside forge-core around rmcp transport adapters, inside forge-daemon session routing, or in a dedicated proxy crate.
