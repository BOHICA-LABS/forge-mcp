# HS-015 — Known-good corpus: well-maintained MCP server (filesystem server)

## Description

Forge MCP's security auditor and conformance suite are run against the official
Model Context Protocol reference server — `@modelcontextprotocol/server-filesystem`.
This is a well-maintained, officially published server from Anthropic that provides
filesystem access tools. As a known-good corpus, it should produce minimal security
findings (the filesystem access pattern is by design, not a vulnerability) and the
conformance suite should pass at a high rate (≥ 90%).

This scenario tests the **false positive rate** of Forge MCP's security auditor.
A tool that produces excessive false positives on well-known, legitimate servers
will erode user trust.

## Setup

1. Install the reference server:
   ```bash
   npm install -g @modelcontextprotocol/server-filesystem
   ```
2. Configure it with a known allowed directory:
   ```json
   {
     "mcpServers": {
       "filesystem": {
         "command": "npx",
         "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp/test-dir"]
       }
     }
   }
   ```
3. Create `/tmp/test-dir/` with some test files
4. Ensure the server starts successfully

## Steps

1. Run `forge-mcp connect filesystem`
2. Run `forge-mcp info filesystem --json` — inspect tool list and capabilities
3. Run `forge-mcp test filesystem --json` — conformance test
4. Run `forge-mcp audit filesystem --json` — security audit
5. Count the number of security findings
6. Classify each finding: true positive, false positive, or informational
7. Calculate the false positive rate

## Expected Behavior

### Conformance
- Conformance suite passes at ≥ 90% of applicable tests
- Any failures should be in optional/edge-case tests, not core protocol
- The server implements tools correctly (read_file, write_file, list_directory, etc.)

### Security Audit
- **Expected true findings (acceptable):**
  - Informational: "Server provides filesystem access" (by design)
  - Low: "write_file could modify files" (documented capability, not a vulnerability)
- **Expected false positives (should NOT appear):**
  - SSRF on filesystem tools (filesystem != network)
  - Path traversal when allowed_directories is properly configured
  - Prompt injection in standard tool descriptions
- Total high/critical findings: 0 (for a properly configured reference server)
- Total medium findings: ≤ 2
- Informational/low findings: acceptable (not counted against FP rate)

### False Positive Rate
- FP rate = false_positives / total_findings
- Target: FP rate < 20% for medium+ findings
- An FP rate > 50% indicates the auditor needs calibration

## Must-Pass Criteria

1. Conformance suite passes ≥ 90% of tests
2. No critical or high severity FALSE POSITIVE findings
3. The server's filesystem tools are correctly identified and listed
4. Security audit completes without errors
5. False positive rate for medium+ findings is < 30%

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Conformance pass rate | < 70% | 70-80% | 80-90% | ≥ 90% |
| False positive rate (med+) | > 50% | 30-50% | 10-30% | < 10% |
| Finding calibration | Critical FPs on known-good server | High FPs on standard patterns | Only low/info for standard patterns | Zero FPs, only legitimate informational |
| Tool identification | Can't list tools | Partial tool list | Complete tool list, missing details | Complete tools with schemas + descriptions |
| Audit completeness | Audit crashes | Audit partial | Audit complete, rough categorization | Audit complete, well-categorized, actionable |
