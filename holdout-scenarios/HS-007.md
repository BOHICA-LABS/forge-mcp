# HS-007 — Conformance test against server with incomplete implementation

## Description

A developer is building an MCP server and claims it supports both tools and resources
capabilities in its `initialize` response. However, the server only correctly implements
the tools capability — calling `resources/list` returns a JSON-RPC `method not found`
error. The user runs Forge MCP's conformance test suite to validate their server.

The conformance suite must handle partial implementations gracefully, report mixed
results (pass for tools, fail for resources), and return the correct exit code to
indicate that not all tests passed.

## Setup

1. Create a mock MCP server that:
   - Responds to `initialize` with capabilities: `{ "tools": {}, "resources": {} }`
   - Correctly handles `tools/list` → returns a list of tools
   - Correctly handles `tools/call` → executes the tool
   - Returns `{ "code": -32601, "message": "Method not found" }` for `resources/list`
   - Returns `{ "code": -32601, "message": "Method not found" }` for `resources/read`
   - Correctly handles `ping` → returns pong
2. Start the mock server

## Steps

1. Run `forge-mcp connect partial-server`
2. Run `forge-mcp test partial-server --json`
3. Examine the JSON output for test results per capability
4. Check the process exit code
5. Run `forge-mcp test partial-server` (human-readable output)
6. Verify the report clearly distinguishes passing vs failing capabilities

## Expected Behavior

- Conformance suite runs all tests for declared capabilities
- Results are categorized by capability:
  - **initialize:** PASS (server responds correctly)
  - **ping:** PASS
  - **tools/list:** PASS
  - **tools/call:** PASS (at least one tool callable)
  - **resources/list:** FAIL (declared but returns method-not-found)
  - **resources/read:** FAIL (declared but returns method-not-found)
- Overall result: FAIL (some declared capabilities don't work)
- Exit code: 1 (indicating test failures)
- JSON output includes:
  - Total tests, passed count, failed count
  - Per-test details with error messages
  - Clear indication that resources were declared but not implemented
- Human-readable output shows a summary table with pass/fail per test
- The report distinguishes between "capability not declared" (skip) vs
  "capability declared but broken" (fail)

## Must-Pass Criteria

1. Conformance suite does not crash when receiving method-not-found errors
2. Tools tests pass (tools capability works correctly)
3. Resources tests fail (resources declared but not implemented)
4. Exit code is 1 (not 0, not crash)
5. Report clearly distinguishes between declared-but-broken vs not-declared

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Error handling | Suite crashes on method-not-found | Suite hangs/times out | Suite completes but miscategorizes | Suite handles gracefully, correct categorization |
| Test accuracy | Wrong pass/fail for > 2 tests | Wrong pass/fail for 1-2 tests | All pass/fail correct, vague details | All correct with detailed error context |
| Exit code | Crashes (non-1 non-0) | Exit 0 despite failures | Exit 1 but inconsistent | Exit 1 exactly, matches test results |
| Report quality | No report generated | Raw errors, hard to read | Structured but missing summary | Clear summary table + per-test details |
| Declared-vs-broken distinction | No distinction made | Mentions it in text only | Separate categories in output | Clear visual/structural separation |
