# SR-001: Clarify Transport-Specific Configuration Fields

## Severity: MEDIUM
## Category: developer-experience
## Location: BC-1.01.002, POST-003

## Description
POST-003 mentions `config (transport-specific fields)` but doesn't explicitly define what these fields are for each transport type. A developer implementing the `StdioConfig` and `HttpConfig` structures will need to infer them from the test vectors or external documentation. The interface definition shows `command`, `args`, `env` for Stdio and `url`, `headers` for HTTP, but this isn't formalized in the BC postconditions.

## Suggestion
Explicitly list the required and optional fields for `StdioConfig` and `HttpConfig` within POST-003 or add a new postcondition defining the struct shapes. For example:
- `StdioConfig` MUST include `command` (string). It MAY include `args` (list of strings) and `env` (map of string to string).
- `HttpConfig` MUST include `url` (string). It MAY include `headers` (map of string to string).
