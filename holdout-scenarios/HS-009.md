# HS-009 — Pagination with misbehaving server (cursor loop)

## Description

A developer connects to an MCP server that implements pagination for `tools/list`
but has a bug — the pagination cursors form a cycle. After page 1 returns cursor "B",
page 2 returns cursor "C", and page 3 returns cursor "A" again, creating an infinite
loop. Forge MCP must detect this cyclic pagination, terminate the loop, return the
partial results already collected, and warn the user about the server's misbehavior.

This tests defensive handling of misbehaving servers — a key robustness requirement
since Forge MCP connects to arbitrary third-party servers (ASM-014).

## Setup

1. Create a mock MCP server implementing `tools/list` with pagination:
   - Request with no cursor → returns tools `[tool_a, tool_b]`, nextCursor: `"page-B"`
   - Request with cursor `"page-B"` → returns tools `[tool_c, tool_d]`, nextCursor: `"page-C"`
   - Request with cursor `"page-C"` → returns tools `[tool_e, tool_f]`, nextCursor: `"page-A"`
   - Request with cursor `"page-A"` → returns tools `[tool_a, tool_b]`, nextCursor: `"page-B"` (CYCLE!)
2. Start the mock server

## Steps

1. Run `forge-mcp connect cyclic-server`
2. Run `forge-mcp info cyclic-server --json`
3. Observe behavior as Forge MCP iterates through paginated results
4. Check output for:
   - Partial tool list (tools collected before cycle detection)
   - Warning about cyclic pagination
5. Check the process exit code
6. Measure wall-clock time (should not hang)

## Expected Behavior

- Forge MCP begins paginating through `tools/list` responses
- After encountering a previously-seen cursor (`"page-A"` → already visited), it:
  - Stops pagination immediately
  - Does NOT enter an infinite loop
  - Does NOT hang or timeout after a long delay
- Returns the partial results collected before cycle detection:
  - At minimum: `tool_a`, `tool_b`, `tool_c`, `tool_d`, `tool_e`, `tool_f`
  - May include duplicates from the cycled page (acceptable if deduplicated)
- Produces a warning (stderr or JSON field) indicating:
  - Cyclic pagination detected
  - The cursor that caused the cycle
  - Number of pages fetched before detection
- Exit code: 0 (partial results returned successfully) with warning, OR
  a specific non-zero exit code for "completed with warnings"
- Total time: < 5 seconds (not blocked in a loop)

## Must-Pass Criteria

1. Forge MCP does not hang or loop indefinitely (terminates within 5 seconds)
2. Partial results are returned (at least the tools from non-cycled pages)
3. A warning is emitted about cyclic pagination
4. The cyclic cursor is identified in the warning
5. Memory usage remains bounded (no accumulation from infinite pagination)

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Loop detection | Infinite loop / hang | Timeout after 30+ seconds | Detects after re-fetching 1 cycled page | Detects immediately on cursor re-encounter |
| Partial results | No results returned | Some results, missing pages | All pre-cycle results, with duplicates | All unique tools, deduplicated |
| Warning quality | No warning | Generic "pagination error" | "Cyclic pagination detected" | Specific cursor + page count in warning |
| Timing | > 30s or hang | 5-30s | 2-5s | < 2s from first request to result |
| Exit code | Crash or unexpected code | Exit 0 silently | Exit 0 with warning on stderr | Appropriate exit code + structured warning |
