# BC-10.25.001 — Response Behavior Delta Testing

## Summary

Issues identical requests to two MCP servers and compares their responses.
Evaluates structural differences (response shape, field presence), semantic
differences (different values for same fields), and timing differences
(latency, throughput). Uses multiple samples for timing comparisons to
establish statistical significance. Primary use cases: staging vs production
validation and version upgrade regression testing.

## Preconditions

| ID | Condition |
|----|-----------|
| PRE-001 | Both MCP servers have completed initialization and are ready to accept requests |
| PRE-002 | Both servers support the methods to be tested (intersection of capabilities) |
| PRE-003 | A test request set has been defined (methods + parameters) |
| PRE-004 | For timing comparison: sample count is specified (default: 10 per request) |

## Postconditions

| ID | Condition |
|----|-----------|
| POST-001 | Identical requests have been sent to both servers |
| POST-002 | Response structure differences are reported (field additions, removals, type changes) |
| POST-003 | Response value differences are reported where meaningful |
| POST-004 | Timing differences are reported with statistical context (mean, median, p95, p99) |
| POST-005 | Statistical significance of timing differences is assessed (t-test or similar) |
| POST-006 | Error handling differences are reported (same request → different error codes) |
| POST-007 | Report identifies which server is "baseline" and which is "target" |

## Invariants

| ID | Invariant |
|----|-----------|
| INV-001 | Requests sent to both servers are byte-identical |
| INV-002 | Timing measurements exclude network overhead where possible (or include it consistently) |
| INV-003 | Statistical significance requires ≥ 3 samples per request |
| INV-004 | Response comparison ignores non-deterministic fields (timestamps, random IDs) unless configured |

## Edge Cases

| ID | Scenario | Expected Behavior | Source |
|----|----------|-------------------|--------|
| EC-001 | One server returns success, other returns error for same request | Reported as behavioral divergence (highest severity) |  |
| EC-002 | Responses are structurally identical but values differ (e.g., different tool descriptions) | Reported as value difference (medium severity) |  |
| EC-003 | Timing difference is within noise range (< 10% difference) | Reported as "no significant difference" |  |
| EC-004 | One server is consistently 10x slower | Reported with statistical significance; flagged as performance regression |  |
| EC-005 | Server returns non-deterministic content (e.g., timestamps, UUIDs) | Configurable: ignore known non-deterministic fields or flag as difference |  |
| EC-006 | One server paginates, other doesn't (same data) | Structural difference in response; content may be equivalent after full pagination |  |
| EC-007 | One server supports method, other doesn't | Skip that method; report as capability difference (defer to BC-10.24.001) |  |
| EC-008 | Servers use different protocol versions | Proceed with comparison on common methods; note version difference | DEC-015 |

## Canonical Test Vectors

### Happy Path

| ID | Request | Server A Response | Server B Response | Expected Delta |
|----|---------|-------------------|-------------------|----------------|
| TV-HP-001 | `tools/list` | `{tools:[{name:"read"}]}` | `{tools:[{name:"read"},{name:"write"}]}` | structural: B has additional tool `write` |
| TV-HP-002 | `ping` (10 samples) | mean: 5ms, p95: 8ms | mean: 50ms, p95: 80ms | timing: B is ~10x slower (statistically significant, p < 0.01) |
| TV-HP-003 | `tools/call {name:"read",arguments:{path:"test.txt"}}` | `{content:[{type:"text",text:"hello"}]}` | `{content:[{type:"text",text:"hello"}]}` | no difference |

### Edge Case

| ID | Request | Server A Response | Server B Response | Expected Delta |
|----|---------|-------------------|-------------------|----------------|
| TV-EC-001 | `tools/call {name:"search",arguments:{q:"test"}}` | `{content:[...], isError:false}` | `{content:[], isError:true}` | behavioral divergence: A succeeds, B errors |
| TV-EC-002 | `ping` (3 samples) | 4ms, 5ms, 6ms | 5ms, 4ms, 6ms | no significant timing difference |
| TV-EC-003 | `resources/list` | `{resources:[...]}` | Error: method not found | capability difference (not behavioral — B doesn't support resources) |

### Error

| ID | Input | Expected Output |
|----|-------|-----------------|
| TV-ERR-001 | Server B disconnects during test | Partial results for completed requests; remaining marked as "error: server disconnected" |
| TV-ERR-002 | Test request set is empty | Error: "no requests to compare; provide at least one test request" |
| TV-ERR-003 | Sample count set to 0 | Error: "sample count must be ≥ 1" |

## Verification Properties

| ID | Property | Method |
|----|----------|--------|
| VP-001 | Requests are byte-identical across both servers | Request logging and comparison |
| VP-002 | Timing statistics are mathematically correct | Unit test on statistics module |
| VP-003 | Statistical significance assessment uses appropriate test (e.g., Welch's t-test) | Validated against known distributions |
| VP-004 | Non-deterministic field filtering is configurable and documented | Config test + default behavior test |
| VP-005 | Behavioral divergences (success vs error) are always flagged as highest severity | Assertion on divergence severity |
