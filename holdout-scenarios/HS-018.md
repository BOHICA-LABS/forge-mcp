# HS-018 — Concurrent TUI and CLI access to same server

## Description

A developer has the Forge MCP TUI open and is inspecting live traffic from an MCP
server. Simultaneously, from a separate terminal window, they run CLI commands that
invoke tools on the same server. Both the TUI and CLI should work without interference
— the TUI should show the CLI-initiated traffic in its inspector, the CLI should
receive correct tool results, and the daemon's session pool must handle concurrent
access from multiple clients without corruption or deadlocks.

This tests concurrent access patterns that are common in developer workflows — using
the TUI for monitoring while scripting tool calls via CLI.

## Setup

1. Start the Forge MCP daemon: `forge-mcp daemon start`
2. Create a mock MCP server with a tool:
   ```json
   {
     "name": "echo",
     "description": "Echo the input back",
     "inputSchema": {
       "type": "object",
       "properties": {
         "message": { "type": "string" }
       },
       "required": ["message"]
     }
   }
   ```
   The `echo` tool returns `{"content": [{"type": "text", "text": "<message>"}]}`
3. Connect to the server: `forge-mcp connect echo-server`

## Steps

1. In **Terminal 1:** Launch `forge-mcp tui`
2. In TUI: Navigate to traffic inspector for echo-server
3. In **Terminal 2:** Run CLI tool invocation:
   ```bash
   forge-mcp call echo-server echo '{"message": "hello from CLI"}' --json
   ```
4. In TUI: Verify the CLI-initiated request/response appears in the traffic log
5. In **Terminal 2:** Run 10 rapid sequential CLI calls:
   ```bash
   for i in $(seq 1 10); do
     forge-mcp call echo-server echo "{\"message\": \"call-$i\"}" --json
   done
   ```
6. In TUI: Verify all 10 calls appear in traffic log
7. In TUI: Simultaneously inspect a tool while CLI calls are running
8. In **Terminal 2:** Run a call while TUI is actively scrolling traffic
9. Verify both CLI results and TUI display are correct
10. In **Terminal 2:** Run concurrent CLI calls (background processes):
    ```bash
    forge-mcp call echo-server echo '{"message": "concurrent-1"}' --json &
    forge-mcp call echo-server echo '{"message": "concurrent-2"}' --json &
    forge-mcp call echo-server echo '{"message": "concurrent-3"}' --json &
    wait
    ```
11. Verify all 3 concurrent calls return correct results
12. Verify TUI shows all 3 calls in traffic

## Expected Behavior

### CLI Behavior
- All CLI tool invocations return correct results (echo returns the input message)
- Each CLI call gets its own JSON response on stdout
- No cross-talk between concurrent CLI calls (each gets its own result)
- Exit code 0 for all successful calls
- No "session locked" or "connection busy" errors

### TUI Behavior
- TUI remains responsive during CLI activity
- Traffic inspector shows ALL CLI-initiated traffic:
  - Request direction: client → server
  - Response direction: server → client
  - Message content matches the CLI input
- TUI can be navigated (panel switch, scroll, inspect) while CLI traffic flows
- No rendering corruption from concurrent updates

### Daemon Session Pool
- Daemon handles concurrent requests from TUI and CLI without:
  - Deadlocks (no hanging)
  - Corruption (no mixed responses)
  - Serialization bottleneck (concurrent calls don't block each other excessively)
- Session to the MCP server is shared or multiplexed correctly
- If sessions are pooled, pool expansion/contraction is invisible to clients

### Data Integrity
- No message mixing: CLI call A's response is never delivered to CLI call B
- No dropped messages: all requests get responses
- Traffic log in TUI is complete and in-order for each direction

## Must-Pass Criteria

1. CLI tool invocations succeed while TUI is active (no conflicts)
2. TUI displays CLI-initiated traffic in the inspector
3. Concurrent CLI calls each return their own correct result (no cross-talk)
4. TUI remains responsive during CLI activity (no freezes or corruption)
5. No deadlocks or hangs under concurrent access

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| CLI correctness | CLI fails when TUI is active | CLI works but intermittent errors | CLI works, rare timing issues | All CLI calls correct, zero errors |
| TUI traffic visibility | TUI doesn't show CLI traffic | Partial CLI traffic shown | All CLI traffic shown, minor delay | Real-time CLI traffic with correct attribution |
| Concurrency handling | Deadlock or corruption | Serialized (one at a time) | Mostly concurrent, occasional queue | True concurrent, no blocking |
| TUI responsiveness | TUI freezes during CLI use | TUI sluggish, noticeable lag | TUI responsive, minor frame drops | TUI fully responsive, no degradation |
| Data integrity | Message cross-talk between calls | Occasional response mismatch | Correct responses, minor ordering issues | Perfect isolation + correct ordering |
