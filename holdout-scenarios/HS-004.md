# HS-004 — Config drift across 3+ editors with dual schema

## Description

A developer uses three editors — Claude Desktop, Cursor, and VS Code — all configured
with a logical server called "my-api". However, each editor uses a slightly different
configuration: Claude Desktop and Cursor use the `mcpServers` schema while VS Code uses
the `servers` schema. The server arguments, environment variables, and transport settings
differ across all three. The user runs Forge MCP's config drift detection to get a
comprehensive report showing all differences with clear editor attribution.

This tests Forge MCP's ability to normalize heterogeneous config schemas and produce
meaningful cross-editor drift analysis.

## Setup

1. **Claude Desktop** (`~/Library/Application Support/Claude/claude_desktop_config.json`):
   ```json
   {
     "mcpServers": {
       "my-api": {
         "command": "node",
         "args": ["server.js", "--port", "3000"],
         "env": { "API_KEY": "claude-key-123", "LOG_LEVEL": "info" }
       }
     }
   }
   ```

2. **Cursor** (`~/.cursor/mcp.json`):
   ```json
   {
     "mcpServers": {
       "my-api": {
         "command": "node",
         "args": ["server.js", "--port", "3001", "--verbose"],
         "env": { "API_KEY": "cursor-key-456", "LOG_LEVEL": "debug", "CACHE_TTL": "300" }
       }
     }
   }
   ```

3. **VS Code** (`.vscode/settings.json` → `mcp.servers`):
   ```json
   {
     "mcp": {
       "servers": {
         "my-api": {
           "type": "stdio",
           "command": "npx",
           "args": ["-y", "my-api-server", "--port", "3000"]
         }
       }
     }
   }
   ```

## Steps

1. Run `forge-mcp discover --json`
2. Verify "my-api" is found in all 3 editors
3. Run `forge-mcp drift my-api --json`
4. Examine drift report for completeness
5. Run `forge-mcp drift my-api` (human-readable)
6. Verify all differences are clearly explained

## Expected Behavior

- Discovery identifies "my-api" in Claude Desktop, Cursor, and VS Code
- Drift report identifies these specific differences:
  - **Command:** `node` (Claude Desktop, Cursor) vs `npx` (VS Code)
  - **Args:** Port 3000 (Claude Desktop) vs 3001 (Cursor) vs different command structure (VS Code)
  - **Verbose flag:** Only in Cursor (`--verbose`)
  - **API_KEY:** Different values across Claude Desktop and Cursor, missing in VS Code
  - **LOG_LEVEL:** `info` (Claude Desktop) vs `debug` (Cursor), missing in VS Code
  - **CACHE_TTL:** Only in Cursor
  - **Schema format:** `mcpServers` (Claude Desktop, Cursor) vs `servers` (VS Code)
- Each difference is attributed to the specific editor(s)
- JSON output includes a structured diff per field
- Human-readable output uses a table or aligned format for easy scanning
- Environment variable values may be redacted (showing "differs" rather than actual values)

## Must-Pass Criteria

1. All 3 editors are discovered and included in the drift report
2. Both schema formats (`mcpServers` and `servers`) are correctly parsed
3. Command, args, and env differences are all identified
4. Each difference is attributed to its source editor
5. JSON output is valid and machine-parseable

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Schema normalization | Cannot parse one schema format | Parses both but misses entries | Parses both correctly, minor normalization issues | Perfect normalization across both schemas |
| Difference detection | Misses > 50% of differences | Finds command/args diffs, misses env | Finds all diffs, minor omissions | Every field difference identified and categorized |
| Editor attribution | No attribution | Attribution for some differences | Attribution for all, minor label issues | Clear, correct attribution with editor names |
| Report clarity | Unusable output | Raw diff, hard to interpret | Structured but dense | Clear table/format, instantly scannable |
| Env var handling | Crashes on env vars | Shows raw values (security concern) | Partially redacted | Smart redaction with "differs" indicators |
