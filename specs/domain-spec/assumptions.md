| ASM-001 | The rmcp crate (`warpdotdev/rmcp`) correctly implements MCP 2025-11-25 transport and protocol handling. Confirmed: rmcp provides `ClientCapabilitiesBuilder` with `enable_sampling()`, `enable_roots()`, `enable_elicitation()`, and `ServerCapabilities` with tools/resources/prompts/logging/completions/tasks/extensions. Forge MCP delegates all protocol logic to rmcp and does not reimplement any transport or framing. | Medium-High | HIGH — Forge MCP would inherit protocol bugs, potentially failing conformance tests. Fallback: contribute upstream patches or maintain a thin protocol-level patch layer. | partially-validated | Run Forge MCP conformance suite against reference servers using rmcp transport. | ASM-002 | Editor MCP config file formats (Claude Desktop, Cursor, VS Code, Windsurf) are stable enough that a parser written today will work for ≥ 12 months without breaking changes. | Medium | MEDIUM — Config parser breaks silently, servers fail to import, discovery degrades. Fallback: version-detect config format and maintain per-version parsers. | unvalidated | Monitor editor release notes for MCP config format changes quarterly. Track config parse failure rate in telemetry. Holdout candidate: yes | CAP-001, R-006 |
| ASM-003 | MCP servers in the wild implement JSON-RPC 2.0 correctly — messages have valid JSON framing, correct id fields, and proper error objects. | Low | HIGH — Elevated from MEDIUM based on domain research: real-world CVEs (CVE-2025-68145/68143/68144 in Anthropic servers, CVE-2025-6515 in oatpp-mcp) demonstrate that even well-known MCP servers have implementation defects. 36.7% SSRF vulnerability rate (BlueRock) implies widespread quality issues. Malformed messages may crash the parser or produce confusing errors. Fallback: defensive parsing with raw-message fallback for display. | unvalidated | Fuzz test the JSON-RPC parser with malformed inputs. Test against 20+ real-world MCP servers. Track parse error rate in traffic capture. Holdout candidate: yes | CAP-009, DEC-002 |
| ASM-004 | The ratatui framework (v0.30+) with crossterm backend provides sufficient rendering performance for 60fps TUI at 100 events/sec ingest rate with < 5MB RSS. | Medium | HIGH — TUI becomes unusable under load, undermining the signature differentiator. Fallback: throttle rendering to 30fps, implement virtual scrolling for large datasets, or switch to alternate terminal backend. | unvalidated | Benchmark TUI rendering under synthetic load: 100 events/sec, measure fps and RSS at 80×24 and ultra-wide (300×80) terminal sizes. | CAP-006, CAP-008, R-005 |
| ASM-005 | A background daemon process with lazy start and idle timeout is a viable architecture for session persistence across CLI invocations on Linux, macOS, and Windows. | Medium | MEDIUM — Session persistence fails on some platforms, forcing cold-start on every CLI invocation. Fallback: optional explicit daemon management (start/stop commands) or per-invocation session caching. | unvalidated | Test daemon lifecycle on all 5 target platforms (Linux x64, Linux ARM64, macOS Intel, macOS ARM64, Windows x64). Survey 5 agent framework authors on acceptable token budgets. | CAP-011, CAP-012 |
| ASM-007 | The MCP 2025-11-25 spec is stable enough that a conformance suite written against it will not require major rework within 12 months. | Medium | HIGH — Domain research confirms spec evolution: 2024-11-05 → 2025-03-26 → 2025-06-18 shows ~6 month cadence between updates (faster than the initial 12-month estimate). 2025-11-25 additions included sampling with tool calling, elicitation, tasks, extensions — significant new surface area. Fallback: version-tag conformance suites and support multiple spec versions. | partially-validated | Monitor MCP spec repository for breaking change proposals. Track spec revision cadence. Note: cadence may be accelerating, which increases rework risk. Holdout candidate: yes | CAP-019, R-002 |
| ASM-008 | Runtime behavioral analysis can achieve acceptable precision (> 80% true positive rate) for dangerous tool pattern detection using rule-based heuristics without requiring an embedded LLM. | Medium-High | HIGH — Elevated confidence: domain research reveals a substantial corpus of known attack patterns (SSRF to 169.254.169.254 metadata endpoints, RFC1918 private IP targeting, known-dangerous tool names, prompt injection patterns). The high false positive risk is primarily in heuristic/behavioral patterns, not in the deterministic category. Fallback: allow user-tunable sensitivity, provide clear confidence scores, start with high-precision/low-recall rules. | unvalidated | Test security heuristics against a corpus of 50+ known-good and 50+ known-dangerous MCP server behaviors. | ASM-009 | Health metric collection from passively observed traffic (no synthetic probes) provides sufficient signal for latency, error rate, and throughput monitoring. | High | LOW — Passive-only metrics are accurate when traffic is flowing but blind during idle periods. Measure coverage gap during idle periods. | CAP-013, DI-008 |
| ASM-010 | Static Rust binaries with LTO can be built at < 25MB for all 5 target platforms while including ratatui, rmcp, clap, tokio, and all security heuristics. | Medium | LOW — Binary exceeds 25MB but remains functional. | ASM-011 | JUnit XML output format is sufficient for conformance test integration with the major CI/CD systems (GitHub Actions, GitLab CI, Jenkins).
