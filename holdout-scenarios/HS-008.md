# HS-008 — Agent workflow: discover → inspect → call in < 500 tokens

## Description

An AI coding agent (e.g., Claude, GPT, Codex) needs to programmatically discover
available MCP servers, inspect one, and invoke a tool — all via Forge MCP's CLI with
JSON output. The agent pipelines commands together using standard Unix tools. The total
token count of all JSON output across the entire pipeline must stay under 500 tokens
to fit within the agent's context budget.

This tests Forge MCP's "agent-friendly" design — compact JSON output, predictable
schema, and composability with standard Unix pipes.

## Setup

1. Configure one editor (VS Code) with a server called "math-server"
2. Start a mock MCP server "math-server" with one tool:
   ```json
   {
     "name": "add",
     "description": "Add two numbers",
     "inputSchema": {
       "type": "object",
       "properties": {
         "a": { "type": "number" },
         "b": { "type": "number" }
       },
       "required": ["a", "b"]
     }
   }
   ```
3. Tool `add` with `{"a": 2, "b": 3}` returns `{"content": [{"type": "text", "text": "5"}]}`
4. Ensure `jq` is available in PATH

## Steps

1. Run the full pipeline:
   ```bash
   forge-mcp list --json | \
     jq '.servers[0].name' | \
     xargs forge-mcp info --json | \
     jq '.tools[0].name' | \
     xargs -I{} forge-mcp call math-server {} '{"a": 2, "b": 3}' --json
   ```
2. Capture the output of each intermediate step
3. Count tokens (approximate: chars/4) for each JSON output
4. Sum total tokens across all outputs
5. Verify the final result is correct (`5`)

## Expected Behavior

- Each command in the pipeline succeeds with exit code 0
- `forge-mcp list --json` produces compact JSON with server names (no verbose metadata)
- `forge-mcp info --json` produces compact tool schema (no redundant fields)
- `forge-mcp call --json` produces the tool result in minimal JSON
- The pipeline composes correctly — each step's output feeds cleanly into the next
- Final output contains the correct result: `5`
- Total JSON output across all 3 commands is < 500 tokens (~2000 characters)
- No stderr pollution that could confuse an agent parser
- All JSON output follows a consistent, documented schema

## Must-Pass Criteria

1. Full pipeline executes successfully (exit code 0 at each stage)
2. Final result is correct (tool invocation returns `5`)
3. Total JSON output across all commands < 500 tokens
4. Each JSON output is valid (parseable by `jq`)
5. No extraneous output on stdout that could break pipeline composition

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Pipeline composability | Pipeline breaks at step 1 | 2 of 3 steps work in pipe | All 3 steps work, minor jq gymnastics | Clean pipeline, minimal jq needed |
| Token efficiency | > 1000 tokens total | 500-1000 tokens total | 300-500 tokens total | < 300 tokens total |
| Output cleanliness | stderr mixed with stdout | Extra non-JSON lines on stdout | Clean JSON, minor whitespace bloat | Minimal JSON, no extra output |
| Schema predictability | Different schema per command | Similar schema, some inconsistencies | Consistent schema, documented | Consistent + documented + examples |
| Result correctness | Wrong result or crash | Correct result, wrong format | Correct result, correct JSON | Correct result, minimal JSON, correct exit code |
