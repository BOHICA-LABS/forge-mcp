# BC-10.24.001 — Capability Set Delta Comparison

## Summary

Compares the negotiated capability sets between two MCP servers. Identifies
which capabilities differ and attributes differences to either server
implementation choices or protocol version differences. Reports both
server-side and client-side capability differences.

## Preconditions

| ID | Condition |
|----|-----------|
| PRE-001 | Both MCP servers have completed `initialize` handshake |
| PRE-002 | `InitializeResult` from both servers is available (including `capabilities` and `protocolVersion`) |
| PRE-003 | Client capabilities sent to both servers during `initialize` are recorded |

## Postconditions

| ID | Condition |
|----|-----------|
| POST-001 | Server capabilities from both servers are compared field-by-field |
| POST-002 | Capabilities present in A but not B are listed as "removed" (from A's perspective) |
| POST-003 | Capabilities present in B but not A are listed as "added" (from B's perspective) |
| POST-004 | Capability sub-fields that differ (e.g., `listChanged: true` vs `false`) are reported |
| POST-005 | Protocol version difference is reported if versions differ |
| POST-006 | Attribution: differences are tagged as "implementation" (same protocol version) or "version" (different protocol version) |

## Invariants

| ID | Invariant |
|----|-----------|
| INV-001 | Comparison uses the negotiated capabilities, not the initially requested ones |
| INV-002 | Protocol version is compared alongside capabilities for attribution |
| INV-003 | Same protocol version + different capabilities → "implementation" attribution |
| INV-004 | Different protocol version + different capabilities → "version" attribution (may also be implementation) |

## Edge Cases

| ID | Scenario | Expected Behavior | Source |
|----|----------|-------------------|--------|
| EC-001 | Both servers have identical capabilities and protocol version | Report: "no differences" |  |
| EC-002 | Same protocol version but different capabilities | All differences attributed to "implementation" choice |  |
| EC-003 | Different protocol versions with same capabilities | Report: protocol version differs; capabilities are identical |  |
| EC-004 | One server has experimental/non-standard capabilities | Non-standard capabilities flagged as "unknown/experimental" in report |  |
| EC-005 | Server returns empty capabilities object | Compared as having no capabilities; all of other server's capabilities are "added" |  |
| EC-006 | Nested capability differences (e.g., `tools.listChanged` differs) | Sub-field differences reported individually |  |

## Canonical Test Vectors

### Happy Path

| ID | Server A Capabilities | Server B Capabilities | Expected Delta |
|----|----------------------|----------------------|----------------|
| TV-HP-001 | `{tools:{listChanged:true}, resources:{subscribe:true}}`, protocol `2025-03-26` | `{tools:{listChanged:true}, resources:{subscribe:true}, prompts:{listChanged:false}}`, protocol `2025-03-26` | added: `prompts`; attribution: implementation |
| TV-HP-002 | `{tools:{}}`, protocol `2024-11-05` | `{tools:{listChanged:true}}`, protocol `2025-03-26` | changed: `tools.listChanged` (absent → true); attribution: version (protocol versions differ) |
| TV-HP-003 | Both identical: `{tools:{listChanged:true}}`, same protocol | No differences |

### Edge Case

| ID | Server A | Server B | Expected Delta |
|----|----------|----------|----------------|
| TV-EC-001 | `{}` (empty capabilities) | `{tools:{}, prompts:{}}` | added: `tools`, `prompts` |

### Error

| ID | Input | Expected Output |
|----|-------|-----------------|
| TV-ERR-001 | Server B fails `initialize` | Error: "cannot compare — server B initialization failed" |
| TV-ERR-002 | Server A returns no `capabilities` field | Error or treat as empty capabilities with warning |
