# HS-001 — Multi-server workflow: discover, inspect, compare

## Description

A developer has 4 editors configured (VS Code, Cursor, Claude Desktop, Windsurf)
with overlapping MCP server configurations. Some servers appear in multiple editors
with slightly different arguments. The user wants to discover all servers across
all editors, connect to 2 specific servers, compare their tool schemas side-by-side,
and export the diff as machine-readable JSON for their team.

This scenario exercises the full happy-path workflow across config discovery,
connection management, schema inspection, and structured output — the core
value proposition of Forge MCP.

## Setup

1. Create 4 editor config files:
   - **VS Code** (`settings.json`): `servers` schema with `my-api` (port 3000) and `db-tools`
   - **Cursor** (`~/.cursor/mcp.json`): `mcpServers` schema with `my-api` (port 3001) and `file-search`
   - **Claude Desktop** (`claude_desktop_config.json`): `mcpServers` schema with `my-api` (stdio) and `db-tools`
   - **Windsurf** config: `mcpServers` schema with `file-search` and `code-review`
2. Ensure `my-api` appears in 3 editors with different transport configs
3. Ensure `db-tools` appears in 2 editors
4. Start mock MCP servers for `my-api` (port 3000) and `db-tools` with known tool schemas
5. `my-api` has tools: `get_user`, `create_order`, `list_products`
6. `db-tools` has tools: `query`, `migrate`, `backup`

## Steps

1. Run `forge-mcp discover --json`
2. Verify output lists all unique servers with editor attribution
3. Run `forge-mcp connect my-api` (picks first available transport)
4. Run `forge-mcp connect db-tools`
5. Run `forge-mcp info my-api --json` — verify tool list
6. Run `forge-mcp info db-tools --json` — verify tool list
7. Run `forge-mcp diff my-api db-tools --json`
8. Verify diff output is valid JSON with tool-level comparison
9. Disconnect both servers

## Expected Behavior

- `discover` finds all 6 server entries across 4 editors, deduplicates to 4 unique servers
- Each server entry shows which editor(s) it appears in
- `connect` establishes stdio/SSE transport as configured
- `info` returns complete tool schemas with inputSchema for each tool
- `diff` produces a structured JSON diff showing:
  - Tools unique to `my-api`: `get_user`, `create_order`, `list_products`
  - Tools unique to `db-tools`: `query`, `migrate`, `backup`
  - No overlapping tools (empty intersection)
- All JSON output is parseable by `jq` without errors
- Exit codes are 0 for all successful operations

## Must-Pass Criteria

1. Config discovery finds servers across all 4 editor config locations
2. Overlapping server names are correctly attributed to their source editors
3. Connection succeeds to at least 2 servers simultaneously
4. Diff output is valid, parseable JSON
5. Total wall-clock time for full workflow < 10 seconds (excluding server startup)

## Satisfaction Scoring Rubric

| Criterion | 0 | 1 | 2 | 3 |
|-----------|---|---|---|---|
| Config aggregation | Finds < 2 editors | Finds 2-3 editors | Finds all 4, minor attribution issues | Finds all 4 with correct editor attribution |
| Connection management | Cannot connect to any | Connects to 1 only | Connects to 2 but unstable | Connects to 2+ simultaneously, clean lifecycle |
| Schema diff accuracy | Diff crashes or wrong | Partial diff, missing tools | Correct diff, minor formatting issues | Perfect JSON diff with all tools categorized |
| CLI output quality | Unparseable output | Parseable but missing fields | Complete JSON, minor schema issues | Clean, documented JSON schema, jq-friendly |
| Workflow timing | > 30s | 10-30s | 5-10s | < 5s |
